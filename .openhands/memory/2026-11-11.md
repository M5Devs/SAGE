## Task 2 — Model 2A TGP coprocessor (Fujitsu MB86234)
- Ported MAME `src/devices/cpu/mb86233/mb86233.{cpp,h}` + model2.cpp TGP
  integration into `include/sage/cpu/tgp.h` / `src/cpu/tgp.cpp` (~2.2k lines):
  `mb86233::Tgp` (regs/ALU/program loop, 4096-word microcode RAM, two 0x200-word
  data banks) and `TgpCoprocessor` (TgpBus impl: program/data/io spaces, host
  FIFOs, bank register, sincos/atan/inv/isqrt lookup units, serialize).
- Wired into Bus: `Board` enum (`Model2A`/`Model2B`), chosen from the loaded ROM
  set (`copro_tgp_tables` region present => 2A). Register windows route to the TGP
  when 2A: ctl1 (halt/boot edge on bit 31), FIFO ctl/status, function ports
  (0x00d00000), FIFO data (0x00884000). TGP advanced in `tick_copro` at 2/3 of
  the i960 rate (50 MHz / 3 clocks vs 25 MHz); `tgp_sync()` runs it forward on an
  empty-FIFO read (same role `copro_fifo_sync` plays for the SHARC).
- vf2 real run (600 frames): TGP uploads 3802 words, boots, runs 30662 insns,
  PC=0x0035 [halted]; activity 6227 cmds in, 1572 results out, 532 table reads.
- Model 2A memory-map deltas found by running vf2 and histogramming unmapped
  accesses (758663 -> 6):
  - luma RAM at **0x12800000** (0x20000, umask32: one byte/32-bit word) vs 2B
    0x11400000 (0x10000, umask16: one byte/half-word). `Bus::luma_index()` helper.
  - texture RAM 0/1 at **0x12000000 / 0x12400000**, each a 0x200000 region
    `.mirror(0x200000)` so the window spans 0x400000.
  - UART at **0x01c80000** (umask16, regs a half-word apart) vs 2B 0x009c0000.
  - 0x01c00040-43 is `.nopw()` on 2A (handled in `write_register` so all widths
    are covered; a write32-only check missed byte/half-word stores).
- Remaining 6 unmapped writes + 25 unmapped reads are genuinely unmapped in MAME
  too (0x01c00024/38/3a/40 writes, 0x01c00024 read, 0x00802008-0x0080200b geo-window
  reads; geo has no read handler on either board).
- `SM2_DEBUG` macro added to `include/sage/hw/compat.h` alongside SM2_WARN/TRACE.
- `main.cpp` prints `Copro (TGP)` + `TGP activity` for 2A, SHARC lines otherwise.
- Standalone self-test (`/tmp/tgp_selftest.cpp`, links `src/cpu/tgp.cpp` alone):
  upload/boot pc=0, commands land in activity, inverse(1.0)=3F000000,
  invsqrt(1.0)=3E800000, atan=0x4000, data ROM word reads back. PASSED.

## Task 3 (continued) — GEO read wiring unblocks vf2
Root cause of the vf2 attract-mode stall (i960 spinning at PC 0x00002EFC,
reading 0x00802008): the GEO function-port *read* path was never wired. MAME's
`geo_r` returns the display-list write pointer at 0x00802008 and the read pointer
at 0x00803008; SAGE's `read8/16/32` only handled the GEO *writes*, so the i960
read open bus (0) forever and never saw the TGP fill the display list.

Fix (`src/bus.cpp`): decode `0x00800000-0x00803fff` in `read_register` (byte
lanes), `read16` and `read32` → `m_geometry.geo_read(offset)`. `Geometry::
geo_read` already returned `m_geo_write_addr` at 0x2008 / `m_geo_read_addr` at
0x3008.

Effect (1500 frames): unmapped reads 285,699 → 9,235; polygons rendered
9,052 → 111,113; the i960 now reaches its idle loop (IP 0x10FA0) and runs
attract mode. Verified the change is causal: stashing just this hunk and
rebuilding reproduces 285,699 / 9,052.

Notes:
- `0x01c00040` (CRX cabinet link) is *written* but never read by vf2, so a
  fabricated "standalone link ready" read there is dead code — not added.
- Remaining 9,234 unmapped reads are 16-bit accesses to 0x00884000 (copro FIFO);
  only `read32` decodes that window. Low volume, not a stall.
- The 3D surface (`SAGE_PPM3D`) still rasterises to alpha-only black
  (0xFF000000) at this frame — polygons reach the rasteriser (95k dest pixels)
  but shading/texture lookup yields 0. Separate follow-up.
- Environment: `cmake`/`ninja` are NOT on PATH after a session reset;
  `pip install --user cmake ninja` restores them in `~/.local/bin`. A build run
  without them is a silent no-op that leaves a stale `build/sage`.

## geo_parse 30 Hz gate — RESULT: INERT for vf2 (proven)
- Applied MAME parity gate in `Bus::trigger_vblank()` (`src/bus.cpp`):
  `if ((m_videoctl & 1) == 0 || (m_framenum & 1) == 0) m_geometry.parse();`
  (`m_videoctl` == MAME `m_videocontrol`, reg `0x0098000c`).
- **vf2 runs `Video control = 0x00000000` → bit0 == 0 → 60 Hz mode → the gate's
  first clause is always true → `parse()` runs every vblank exactly as before.**
  MAME behaves identically for vf2. So the gate is a **no-op for vf2**.
- A/B proof: baseline vs gated, frames 900..1499 → identical 372 empty frames;
  concatenated composited-pixel md5 identical (`aa8fc5571b59ab2af07814981c77eb5e`);
  0/61 differing frame files.
- The gate IS correct MAME parity and only affects genuine 30 Hz-mode games
  (e.g. Sega Rally); keep it, but it does NOT fix vf2's empty/black 3D frames.
- Empty-frame pattern is NOT strictly alternating: run-length analysis of
  composited black-fraction over frames 600..1500 → 66 runs; long leading run of
  132 then 320 non-black; mostly 1-frame black spikes; lag-1 autocorr 0.85.
- `SAGE_PPM` dumps the *composited* frame (Video::rgba); `SAGE_PPM3D` dumps the
  raw geometry surface. The geometry surface legitimately contains opaque black
  `0xFF000000` in half-screen blocks on some frames (1052,1056,1076,1081,1084-85)
  — that is the rasteriser writing alpha=0xff with r=g=b=0, not the compositor.

## vf2 geometry stall + heap-corruption fix (commit 33aa5cc, pushed origin/main)
- Diagnosed the ~frame 1650 stall: polygon pool index wrap → cyclic sorted-list
  → infinite loop in `render_polygons`. Fixed by dropping polygons on pool
  exhaustion instead of wrapping (matches reference/MAME).
- The wrap was masking a desynced display list. ASan then found a chain of OOBs:
  `get_texel` texture read (fixed with word-count guard like the reference),
  `process_polygon` texture point/header fetch (bounded via tex_source/tex_read),
  `cmd_polygon_data` write past polygon RAM, and finally Release-only SIGSEGVs in
  `cmd_texture_parameters` (unmasked index) and `parse_np_s` (unbounded vertex
  count) — these last two don't trip ASan because there's no redzone hit before
  the real overrun in Release.
- Bounded all count-driven readers with `geo_words_left()`; capped object vertex
  count to `(region_words-6)/10`; masked the texture-parameter table index.
- Evidence: release 12000 frames rc=0 (~160 s, ~200 s emulated), ASan clean to
  6000 frames, 36/36 ROM ICs verify, frame 2000 render has 34 distinct colours.
- Note: TASK 1's explicit deliverable (vf2 ROM loader, 36/36 ICs) was already
  present from commit 9d50d34; this session's real work was the stall/crash fix.
